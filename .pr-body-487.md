Closes #487

## Why

#487 said a Codex subagent sits on the mesh until its first Murmur tool call, because every Codex session starts Murmur's MCP server. Run on the laptop, that turns out not to be so. What was really left is that first call: it went out as an ordinary session's, and the subagent showed in `who` until the daemon's next read of Codex's state.

What Codex does (0.164, the terminal daemon's version, and 0.167; `codex exec` and `codex app-server`; a scratch MCP server that logged its environment and every request; 2026-11-12):

- A person's thread gets its MCP servers when the thread starts, before any turn.
- A subagent gets an MCP server only for its first call to that server's tools, about 15 ms before the call. With two servers configured and the subagent calling one, the other never started. A subagent that calls none of Murmur's tools never has a Murmur server.
- The environment is bare, and `initialize` carries nothing about the thread. The first tool call does: `_meta.threadId`, and in `_meta["x-codex-turn-metadata"]` `thread_source` (`"subagent"`, or `"user"` for a person's thread), `parent_thread_id` and `subagent_kind: "thread_spawn"`.

## Change

- **The MCP server** reads `thread_source` and `parent_thread_id` from a Codex call (`codexCallOf`). Outside T3, a Codex session's server holds its first hello for up to a second (`holdFirstHello`). A subagent's server gets its call within milliseconds and registers with `Child` and `ParentNative` in its route. If the route changes after registering, the server tells the daemon before the call goes on, not in the background.
- **The route** carries `child` and `parentNative` (protocol 20). It mirrors the hook request's fields from #473.
- **The daemon** makes such a session a child in `hello` and in `setRouteLocked` (`routeChildLocked`), only outside T3 and only for Codex, as it takes Codex's state. A session that is a child when it registers logs no `SessionStarted`.
- Reading Codex's state stays as the fallback, for servers from before this change.

A person's Codex thread outside T3 now registers up to a second after its thread starts. Before, it registered at once.
